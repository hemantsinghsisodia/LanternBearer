# Phase E: Menus, Settings and Keeper's Log — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the main menu, pause menu and Keeper's Log in the forged-iron and amber look, and add one Settings screen covering Display, Graphics, Audio, Accessibility and Controls.

**Architecture:**
- A small themed uGUI widget kit lives in a new `LanternKeeper.UI` assembly. It is styled from `UITheme`, and it also holds the persisted `UserSettings`.
- Screen scripts in Assembly-CSharp compose the kit. An editor builder, **Lantern Keeper → Build UI**, generates the screen prefabs, and the island and menu builders place those prefabs.
- Pure maths (volume to dB, brightness to EV, flashing caps) lives in the Logic assembly.

**Tech Stack:** Unity 6 (6000.6.3f1), URP Deferred, uGUI, TextMeshPro, AudioMixer, NUnit EditMode and PlayMode tests, and the Unity MCP.

**Spec:** `docs/superpowers/specs/2026-10-06-ui-phase-e-design.md`. Its parent is `docs/superpowers/specs/2026-10-03-art-direction-design.md`.

## Global Constraints
**Style (forged iron and amber):**
- Ink panels with thin double brass frame lines. Amber marks the one primary action on each screen.
- Fonts: titles use Cormorant Garamond (`UITheme.titleFont`), flavour text uses Spectral Italic (`flavourFont`), and UI text and numbers use Inter (`uiFont` / `uiFontStrong`). No visible text may use LiberationSans or the TMP default font.
- Signal colours are the `LookPalette` values and are never reused for other meanings. Amber `#FFB15C` means primary or safe warmth.

**Readability:**
- Body text is at least 18 px at 1080p at text scale 1.0 (`UITheme.MinReadableHudFontPx`).
- At text scale 1.3, no label may overflow its row or button, at both 1920×1080 and 1280×720.

**Technology:**
- uGUI + TextMeshPro, with authored prefabs under `Assets/Game/Prefabs/UI/`. No UI Toolkit.
- `HUD.cs` loses only its pause panel code. The HUD itself is Phase F.

**Navigation:**
- Mouse, keyboard and gamepad all work on every screen.
- Every screen has a first-selected element.
- Escape or gamepad B goes back exactly one level. Back returns focus to the button that opened the child screen.
- Fades and page turns use unscaled time, so they work while paused (`Time.timeScale = 0`).

**Settings:**
- Changes apply immediately and are persisted. There is no Apply button.
- PlayerPrefs keys are prefixed `LanternKeeper`.

**Values:**

| Setting | Value |
|---|---|
| Volumes | 0–1, default 0.8. `dB = linear > 0.0001 ? 20·log10(linear) : -80` |
| Brightness | −1 to +1, default 0, mapped to ±1 EV added to the base `postExposure` |
| Text scale | 1.0, 1.15 or 1.3 |
| Reduce flashing | Caps the lightning exposure pulse and `Flash01`-driven brightening at 0.35 of peak, and halves the low-fuel pulse frequency |

**Gameplay:** unchanged. Terrain, scenes' world content, level logic and the HUD's gameplay readouts are untouched.

**Performance:** no island or preset may regress more than 0.3 ms average against `docs/look/perf/2026-10-05-phase-d2.md`.

**Unity process:**
- Never revert, edit or commit `Assets/Settings/UniversalRenderPipelineGlobalSettings.asset` while the editor is open.
- Revert pure noise before committing: `Materials/Generated/ShadeBody.mat`, `Smoke.mat`, `ProjectSettings/*`, Look volumes, `Shade.prefab`, `Keeper.controller`, and scenes or terrain that only re-serialised. Check with `git diff --ignore-space-at-eol --stat`.
- Delete `Assets/Resources/PerformanceTestRun*` if it appears.
- Restore the `LanternKeeperGraphics` PlayerPref to 0 after any capture.
- Never `git checkout` the whole Scenes folder.
- Screenshots go to `.superpowers/sdd/2026-10-06-ui-phase-e/shots/`.
- If the MCP drops for more than about 2 minutes, or a git action is denied, stop and report.

**Model split (AGENTS.md):** implementers and reviewers run on Sonnet.

**Test access:**
- EditMode tests reference `LanternKeeper.Logic`, `LanternKeeper.Look` and the new `LanternKeeper.UI`.
- Assembly-CSharp types are reached by reflection, `Type.GetType("LanternKeeper.X, Assembly-CSharp")`, which is the existing pattern.

## Review Focus
1. **A saved resolution the current monitor doesn't support** (an unplugged monitor, a changed display). Settings must fall back to the current desktop resolution, never apply an invalid mode, and the dropdown must show the fallback. Test: `UserSettingsTests.InvalidSavedResolutionFallsBack` (Task 2).
2. **Opening Settings from pause, then pressing Back with a gamepad.** Focus must return to the pause menu's Settings button and must not land on nothing. The same applies to Log to Back on the main menu. Test: `MenuNavigationTest.BackRestoresOpenerFocus` (Task 8).
3. **Text scale 1.3 at 1280×720.** No row or button label may overflow or clip, and long Log entries must still fit their page, flowing to the next page if needed. Test: `UiLayoutTests.NoOverflowAt130Percent` (Task 8).
4. **Volume set to 0, and old saves with "Music: Off".** Zero must mean −80 dB, which is silent. Old saves must keep music silent until the player raises it. Tests: `SettingsMathTests.ZeroVolumeIsSilent` and `UserSettingsTests.MutedMusicMigratesToZero` (Task 2).
5. **Lightning while Reduce flashing is on and the player also raised Brightness.** The pulse must sit on top of the user's base exposure, and when the flash ends it must return to that base, not the authored base. Test: `SettingsEffectTest.LightningReturnsToUserBrightness` (Task 4).
